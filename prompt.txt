**성능 (원칙 5 — 핫패스 인라인)**

`if`/`while` 같은 핵심 제어가 인자함수(콜백)이면 호출 비용이 걱정된다. lmnop은 의미론은 "전부 인자함수"로 통일하되, 컴파일러가 이들을 **인라인**해 콜백 호출 비용을 0으로 만든다. 열린 코어(무엇이든 함수로 재정의 가능)를 유지하면서도 네이티브 성능을 지키는 것 — 이것이 이 언어의 승부처에 대한 답이다.



이거 새로 만든 mec 때문에 지워도 될것 같은데 맞지?

그리고 또 다른 언어에 문법을 좀 탐구를 해 봤거든 그런데 M.G.S 2.0 언어에서 재미있는 문법을 발견했어

```mgs
local brick where 
   name == "door" 
   and color == "red"
do

end
```

이게 brick 클래스인 모든 객체를 순회해서 만약 name 이 "door" 이고 color 가 "red" 면 do 와 end 사이에 있는 실행하는거래

뭐 나중에 이런식으로 우리도 어떤 한 모든 그 클래스 객체를 순회하는 저런거 만들면 좋을것 같아

음 먼저 정보 지향에 의해 i < 3 이런게 즉시 평가되지 않아, 이게 정보지향이야 i < 3 이건 기본적으로 true 긴 하지만 타입을 조건 (conditions) 로 명시하면 condition.first, condition.second 이러면 condition.first 는 i, contition.second 는 3, condition.opeartor 는 Opeartor.lessThan 이런식으로 이게 정보지향이야 내가 말한 정보지향 그런데 궁금할수도 있는데 타입 명시에 따라 값이 봐뀌는거 이거 이름매직이잖아 근데 먼저 이 lmnop 중 이름 매직 없음은 중요한게 아니야, 아니 그냥 참고만 하라는거지 그러니까 이거야 Clean Code 의 저자 로버트 C 마틴이 continue 그런거 싫어하잖아 하지만 가끔 쓰잖아 이런거야 이름 매직이 내 기준에선 그리고 뭐 x <> 0 and 10 ~/ x > 1 이런건 그냥 condition.equations 로 x <> 0 과 and  랑 10 ~/ x 랑 > 1 이런걸 다 리스트로 얻을수 있어 (...condition) 타입인거지 또한 이게 정보지향이야 내가 말한 정보지향은 이거야
